AlgTop: repair Group-3 orphans and their dependency chain, for the keep/delete question

Fixes first-elaboration bugs in six never-compiled AlgTop modules -- the
26-module "Group 3" set (superseded only in role by
CharClass.LemmaTwoStatement.false_of_stepC_stepD, no declaration duplicated
anywhere) plus part of the dependency chain one of them needs -- so the
compiler's own verdict can settle whether the route not taken is worth
keeping. Nothing wired; still orphaned pending that decision.

* ChernNewtonSquareZero.lean -- three copies of the same bug: `hnewton : ∀ k,
  0 < k -> (k : A) * c k = ...` left `k` untyped. `Finset.antidiagonal` is
  polymorphic over any `HasAntidiagonal` type as of the current pin (it used
  to be Nat-specific), so with no annotation the `(k : A)` ascription a few
  tokens later pinned `k : A` directly instead of coercing a `ℕ`, breaking
  every later use of `k` as an index into `c : ℕ -> A`. Added `: ℕ` at all
  three binders.
* ChernNewtonIdentity.lean -- one unused hypothesis (`hq : 0 < q`, never
  referenced in the proof), renamed to `_hq`.
* ComplexProjectiveChart.lean -- two instances of `rw`'s single-instantiation
  limit: `rw [normalize]` rewrites only the first textual occurrence of a
  `∀`-quantified equation's LHS, not every instantiation, so a goal
  mentioning `normalize u a` and `normalize u b` only had the first unfolded;
  listed `normalize` twice. Similarly `sq` only fired on one of two `_^2`
  occurrences; replaced the tail of that rewrite chain with `ring`, which
  closes what was already a trivial `r^2 = r*r` identity.
* ComplexProjectivePuncture.lean -- `push_neg` is deprecated at this pin
  (`push Not`); three trailing tactics (`ring`/`exact ...` after
  `rw`/`field_simp`) are dead code now -- the preceding tactic's own
  automatic rfl-closing already discharges the goal at the current pin,
  confirmed by re-probing: attaching them with `<;>` (which tolerates zero
  remaining goals) still tripped the unreachable-tactic linter, so they are
  genuinely unreachable and were deleted, not merely guarded; one
  `simpa only [...] using continuous_const.sub continuous_id` failed on a
  syntactic (not definitional) mismatch between pointwise function
  subtraction and an explicit subtraction lambda -- replaced with
  `simp only [...]; fun_prop`.
* ComplexProjectivePunctureRetract.lean -- `ext z` on a `ContinuousMap`
  equality between matrix-valued maps over-chained into `Matrix.ext` one
  level further than the proof anticipated (same shape as today's earlier
  `STW/` repair); replaced with `apply ContinuousMap.ext; intro z` to stop at
  exactly one level. One more dead trailing tactic after a closing `rw`,
  deleted for the same confirmed reason as above.

Probed together with lixprobe10.sh lix-meta (own clone, thm-d, not
lix-orphans' orph-algtop, which is mid-repair on a different group).
23 of the 26 Group-3 modules, plus ChernSeries/ComplexProjectiveSphere/
CupProduct/CupAssoc/CochainLeibniz/Kronecker/ComplexProjectivePuncture/
ComplexProjectivePunctureRetract (the non-Group-3 AlgTop dependencies these
26 need, also never compiled before today) now build clean.

Two things NOT fixed here, reported rather than guessed past:

* SingularCohomology.lean (Group 3) -- `cyclesMk_smul`/`cocycleClass_smul`
  fail: `HomologicalComplex.cycles` at this pin surfaces its element type
  through `forget₂ (ModuleCat R) Ab`, which forgets the `R`-scalar action, so
  `s • (cyclesMk ...)` has no `HSMul R _ _` instance. This is isolated --
  every other declaration in the file (additive structure, pullback,
  homotopy invariance) uses only the group structure and is unaffected, and
  nothing reachable from the other 25 modules needs the `R`-linearity these
  two state. Needs real category-theory work (recovering the module
  structure across the forgetful functor, or restating over the ModuleCat
  hom directly), not a rename.
* ComplexProjectiveProduct.lean (Group 3) needs ComplexProjectiveSphere,
  which needs Cover -> PunctureRetract -> Puncture -> Hyperplane -> Chart ->
  Basic (reachable). Puncture and PunctureRetract are fixed here (same
  genre of bug as above, all shallow). Cover has two more of its own
  (a `Fin.sum_univ_one`-vs-manual-unfold mismatch, two `Subsingleton
  (Fin (0+1))` instance gaps) not yet fixed -- stopped there rather than
  keep descending an unbounded chain outside the 26-module scope; Hyperplane,
  Chart, and Basic's reachable status were not re-examined past what
  lix-orphans already established.
