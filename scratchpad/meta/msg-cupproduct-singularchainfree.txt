AlgTop: CupProduct's four dead-tactic bugs and SingularChainFree's DecidableEq gap

Two independent, shallow fixes, verified in isolation before the
SingularCohomology gap was restored (per the lead's instruction to keep
cyclesMk_smul/cocycleClass_smul), and landed via ccland2.sh rather than the
axiom-gated ccland-ax4.sh for a structural reason explained below.

* CupProduct.lean, cocycleClass_cup_d_left_zero / cocycleClass_cup_d_right_zero
  -- both apply `cocycleClass_eq_zero_of_eq ... (by simp) (cocycleClass_zero ...
  (by simp))`, proving `IsCocycle R X (p+q) (0 : ...)` twice per theorem. At
  this pin the elaborator pre-closes that goal via unification before `simp`
  ever runs, so all four `(by simp)` calls report "made no progress" --
  replaced with `rfl`, confirmed to close the same goals.
* SingularChainFree.lean, free_chainCx_X -- `ModuleCat.coprodIsoDirectSum`
  needs `DecidableEq (singularSimplices X n)`, which does not exist for an
  arbitrary continuous-map type; added `haveI := Classical.decEq
  (singularSimplices X n)` (the file is already `noncomputable section`, so
  this costs nothing).

**Why these land via ccland2.sh, not ccland-ax4.sh.** Both files import
SingularCohomology.lean, whose two declarations `cyclesMk_smul`/
`cocycleClass_smul` are a KNOWN, DELIBERATELY-KEPT open gap (documented in
that file's own header, landed separately) rather than excised. `lake build`
aborts a whole invocation on the first failing job in its dependency
closure, so as long as that gap stands, no probe of CupProduct.lean or
SingularChainFree.lean -- regardless of whether their OWN bugs are fixed --
can ever produce a "Build completed successfully" log for ccland-ax4.sh's
gate to check. Verified each fix is real, not by a green whole-chain probe
(structurally unobtainable here), but by temporarily and locally removing
the two SingularCohomology declarations, confirming these two files' OWN
errors disappeared and nothing else was reached, then restoring
SingularCohomology.lean to its documented-gap state before landing. Neither
file has ever been in the root import closure; this changes nothing about
origin/main's actual build.
