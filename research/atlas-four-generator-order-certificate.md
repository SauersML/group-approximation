## Proof

Work in one `GL_4(F_2)` chart.  Multiply the six adjacent transvections over
`F_2` to form

```text
a = p_0 p_1 p_2 = x_01 x_10 x_12,      b = p_3 p_5 p_4 = x_21 x_32 x_23,
```

and close `{a, b}` under right multiplication by breadth-first search on
`4x4` matrices over `F_2`, keying states by their raw byte encoding.  The
closure has exactly

```text
20160 = (2^4-1)(2^4-2)(2^4-4)(2^4-8) = |GL_4(F_2)|
```

elements, so `<a, b>` is the whole chart.  The enumeration is exact: entries
are bits, the multiplication is `F_2` matrix multiplication, and the state
set is compared by equality, not by any tolerance.

Run the same pair in the second chart.  The two chart groups generate
`Q = L_(F_2)(1,2)^x` by the Steinberg identities (7) of
`notes/EXPLICIT_LEAVITT_ATLAS.md`, so the four resulting units generate `Q`.

Reproducer: `python experiments/atlas_four_generator_certificate.py`.

Two things this route does **not** prove.  It does not show four is the
minimum number of generators of `Q` — only that four suffice.  And it says
nothing about `Q` beyond generation; in particular it neither uses nor
supplies the nonsoficity of `openai-leavitt-unit-nonsofic`, which is what
makes `Q` the interesting place to run the Kaplansky search.
