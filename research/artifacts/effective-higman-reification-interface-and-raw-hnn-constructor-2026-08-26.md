# Effective Higman reification: exact interface and first raw constructor

**Scope.**  This is a zero-literature design/audit of the layer that must turn
finite-rank recursively enumerated relators into an actual
`PresentationCodes.PresentationCode` and explicit words for the embedding.
It is independent of the unfinished semantic proof of `Higman.REBenign`: even
after that structure is inhabited, the present semantic endpoint does not
compute a finite presentation.

No Lean or MSI run was used for this audit.

## 1. The total input and the exact output theorem

Fix an offset rank `n` and put `q = n + 1`.  For a partial-recursive program
code `e`, use the repository's total decoder

```text
EnumeratedPresentationCodes.rawRelator e a : RawWord
```

and define the normal subgroup

\[
 N_{n,e}=\left\langle\!\left\langle
   \operatorname{rawToFree}(n,\operatorname{rawRelator}(e,a)):
   a\in\mathbb N
 \right\rangle\!\right\rangle
 \triangleleft F(\operatorname{Fin}(q)).
\]

This definition is total for every program code.  Failed computations merely
decode to the empty relator, exactly as in
`EnumeratedPresentationCodes.relatorSet`.  No semantic promise is needed to
state the compiler.

For `sigma : Nat -> RawWord`, let `substRaw sigma v` replace a positive letter
`(i,true)` by `sigma (i % q)`, a negative letter by its formal inverse, and
concatenate.  For a finite-presentation code `c`, let

```text
targetEval c w =
  evalRaw (fun i => (PresentedGroup.of (letterOf c i) : Carrier c)) w.
```

The correct proof-relevant compiler interface is:

```text
structure EffectiveFiniteRankHigmanCompiler where
  compile  : Nat -> Nat.Partrec.Code -> PresentationCode
  embedRaw : Nat -> Nat.Partrec.Code -> Nat -> RawWord

  computable_compile : Computable (fun p => compile p.1 p.2)
  computable_embedRaw :
    Computable (fun z => embedRaw z.1.1 z.1.2 z.2)

  exact_kernel : forall n e v,
    targetEval (compile n e) (substRaw (embedRaw n e) v) = 1
      <-> rawToFree n v in N(n,e)
```

The `Nat`-indexed words are intentional.  A function returning
`Fin (genCount ...)`-dependent free-group elements is awkward for Mathlib's
`Primrec` API; `RawTransform` already demonstrates that raw list surgery is
the robust route.

The kernel iff immediately gives the desired embedding.  The substitution
map extends to a homomorphism

\[
 F(\operatorname{Fin}(q))\longrightarrow
 \operatorname{Carrier}(\operatorname{compile}(n,e)),
\]

its kernel is exactly `N(n,e)`, and therefore it descends to an injective map

\[
 F(\operatorname{Fin}(q))/N_{n,e}
 \hookrightarrow \operatorname{Carrier}(\operatorname{compile}(n,e)).
\]

For an arbitrary explicitly enumerated r.e. normal subgroup `N`, choose an
enumerator whose range is `N`; normality gives `N(n,e) = N`.  Thus the total
normal-closure formulation loses no generality and avoids baking a promise
into the executable function.

## 2. Why semantic Higman cannot be postprocessed into this interface

The current semantic chain ends at

```text
fpOvergroup_of_fgRecursive :
  REBenign -> FGRecursive G -> Nonempty (FPOvergroup G)
```

and `FPOvergroup G` contains an abstract type `K`, a `Group K` instance, an
`IsFinitelyPresented K` instance, and an abstract embedding `G ->* K`.
Before that, `Benign N` is itself only `Nonempty (BenignWitness N)`.  Neither
object contains:

* a finite generator numbering for `K`;
* a finite relator list;
* words for the images of the source generators; or
* a program computing any of those objects from `e`.

`PresentationCodes.exists_code_mulEquiv` cannot fill this hole.  It chooses a
code from an already given `IsFinitelyPresented` witness, noncomputably, and it
does not return words for an input-dependent embedding.  Likewise,
`Group.IsFinitelyPresented` proves existence and deliberately forgets the
chosen presentation.

Therefore there is no separate “reify after semantic Higman” function from
the existing endpoint.  Effectivity has to be carried through the Higman
construction.  The semantic proof can remain the correctness oracle, but the
executable construction must retain syntax alongside it.

The minimal strengthened intermediate object is a coded benign witness:

```text
structure CodedBenignWitness (n e) where
  ambient : PresentationCode
  embRaw  : Nat -> RawWord
  lRaw    : List RawWord
  computable data from (n,e)

  emb_exact : source words have the asserted values in Carrier ambient
  emb_injective : F(Fin (n+1)) -> Carrier ambient is injective
  intersection_exact : forall v,
    ambientValue embRaw v in closure { ambientValue id l | l in lRaw }
      <-> rawToFree n v in N(n,e)
```

The semantic `BenignWitness` is recovered by forgetting the code and taking
the subgroup generated by `lRaw`.  The reverse direction is unavailable;
that asymmetry is the reason a new effective layer is necessary.

## 4. First concrete constructor: a raw HNN code

This is the smallest constructor worth implementing first because both the
benign closure machinery and the rope use HNN extensions repeatedly.

Let `c = (m,R)` and `q = genCount c = m+1`.  Given a finite list

```text
edges : List (RawWord x RawWord)
```

define the old-letter shift

```text
shift_c(w) = w.map (fun (i,sign) => (i % q + 1, sign)).
```

Index `0` is the new stable letter and indices `1,...,q` are the old letters.
Define

```text
hnnRel_c(u,v) =
  [(0,true)] ++ shift_c(u) ++ [(0,false)] ++ invWord (shift_c(v))

rawHNNCode(c,edges) =
  (q, R.map shift_c ++ edges.map (fun p => hnnRel_c(p.1,p.2))).
```

The stored count is `q`, so the output alphabet has size `q+1`.
Every operation in this definition is `Nat.mod`, successor, `List.map`,
append and `invWord`; the `Primrec` proof is a direct specialization of the
lemmas already used by `RawTransformPrimrec`.

### Correctness theorem

Index `edges` by `I = Fin edges.length`.  In `Carrier c`, let `a_i` and `b_i`
be the values of the two words in edge `i`, and put

\[
 A=\langle a_i:i\in I\rangle,\qquad
 B=\langle b_i:i\in I\rangle.
\]

Assume an equivalence `phi : A ~=* B` satisfying `phi(a_i)=b_i` for every
`i`.  Then

\[
 \boxed{
 \operatorname{Carrier}(\operatorname{rawHNNCode}(c,edges))
 \cong
 \operatorname{HNNExtension}(\operatorname{Carrier}(c),A,B,\phi).
 }
\]

Moreover the equivalence sends the output generator `0` to the stable letter
and generator `i+1` to `HNNExtension.of(PresentedGroup.of i)`.  Hence for every
raw old-base word `w`,

\[
 \boxed{
 \operatorname{targetEval}(\operatorname{rawHNNCode}(c,edges),
      \operatorname{shift}_c(w))=1
 \iff
 \operatorname{targetEval}(c,w)=1.
 }
\]

### Proof

Use `PresentedGroupRelabel.optionFinEquiv q`, which sends `none` to `0` and
`some i` to `i+1`.

1. For each raw word `w`, letter-by-letter reduction modulo `q` gives
   \[
   \operatorname{wordOf}(\operatorname{rawHNNCode},\operatorname{shift}_c(w))
   =\operatorname{relabel}(\operatorname{optionFinEquiv},
      \operatorname{HNNPresentation.emb}(\operatorname{wordOf}(c,w))).
   \]
   The only arithmetic is `(i % q)+1 < q+1`.
2. The one-letter word `[(0,true)]` reads as the relabelled
   `HNNPresentation.stableWord`.
3. By the two reading identities and `RawWord.wordOf_invWord`, each generated
   `hnnRel_c(u,v)` reads as the relabelled HNN relator
   `t * u * t^-1 * v^-1`.
4. Therefore the output relator set is exactly the relabelling, by
   `optionFinEquiv q`, of
   `HNNPresentation.hnnRels` applied to the input relator set and the edge
   words.  List membership handles duplicates and needs no decidable quotient
   equality.
5. Compose, in order:
   `PresentationCodeList.carrierOfList`, transport along the relator-set
   equality, `PresentedGroupRelabel.congrEquiv`, and
   `HNNPresentation.equivPres`.  This proves the displayed group equivalence
   and its generator formulas.
6. The final kernel equivalence follows because `HNNExtension.of` is
   injective.

This is a complete proof of the constructor's semantics; the absent Lean work
is the raw definition, the four reading lemmas, and the routine `Primrec`
assembly.

The first immediately useful specialization is

```text
centralHNNCode(c, L) = rawHNNCode(c, L.map (fun w => (w,w))).
```

Here `A=B` and `phi` is the identity, so no edge-isomorphism search is needed.
This is exactly the first extension in `Higman.RopeTrick`.

## 5. The remaining mechanical constructors

After `rawHNNCode`, the rope needs only three finite syntactic operations.

1. **`rawProductCode(c,d)`.**  Start from the disjoint-union/free-product code
   and append one commutator relator for every pair of numbered generators.
   Correctness is `ProductFinitePresentation.ker_eq_normalClosure` plus the
   already-proved `CoprodCode.coprodCodeEquiv`.
2. **`adjoinGeneratorRelators(c,L)`.**  Shift old letters by one, reserve `0`
   for a new generator, and append the finite raw list `L`.  This is the HNN
   constructor without an edge theorem and is immediate from equality of
   relator sets.
3. **`rawAmalgamCode(c,d,edges)`.**  Use the free-product code and append
   `left(u) ++ invWord(right(v))` for each edge pair.  Under the supplied
   generated-subgroup equivalence, correctness follows from
   `AmalgamPresentation.Rel_eq_of_closure` and `AmalgamPushout.equivPush`.

The rope itself can then be reified from a `CodedBenignWitness`:

```text
gamma := centralHNNCode ambient lRaw
pre   := rawProductCode gamma (freeGroupCode n)
out   := adjoinGeneratorRelators pre (finite A/B rope relations)
```

The embedding words are the words of the free-group factor inside `pre`.
Transporting `Rope.ropeEquiv` and `Rope.quotientEmb_injective` through the
three constructor equivalences proves the final `exact_kernel` iff.  No
enumerated relator is copied into the output: the finite detector list
`lRaw` is the compression supplied by benignness.

## 6. True first missing boundary

There are two meanings of “first missing constructor,” and they should not be
conflated.

* The first missing **mechanical presentation constructor** is
  `rawHNNCode`; its semantics are proved above and it is small.
* The first missing **effective Higman datum** is `CodedBenignWitness`.
  Closing semantic `REBenign` does not construct it.  The operation-closure
  proof must either be re-run with coded witnesses or strengthened so every
  closure returns the ambient code, detector words and embedding words.

Thus the safe implementation order is:

1. raw substitution and its evaluation theorem;
2. `rawHNNCode` and `centralHNNCode`, including `Primrec`;
3. raw product/amalgam/adjoin-relator constructors;
4. `CodedBenignWitness` and effective closure combinators;
5. the coded rope compiler and final kernel iff;
6. only then inhabit `FinitePresentationSwitchCompiler`.

The final `Pi^0_2` hardness theorem must remain conditional until both the
semantic benignness chain and this effective, proof-relevant chain are closed.
