# Bijective designs force every finite presentation as their table core

Lane `gk-n-twocycle`, 2026-09-12. Handwritten proofs; nothing was run.
Supports `bijective-designs-force-every-finite-presentation`.

**Question.** The design program asks for a strict rule pair whose minimal forward
sufficiency forces a nonsofic, ideally Kazhdan, core with at least two independent
cycles. `defect-window-automaton-over-leavitt-units` records its death point as: no
rule pair is known whose forward sufficiency needs a Kazhdan presentation.

**Answer.** Forcing is free. Shift–shear designs force any finite presentation,
which covers every Kazhdan presentation and every nonsofic one, as the canonical table
group. They are bijective over every group, so a forced core never certifies
strictness by itself. All of strictness lives in the reverse hinges.

Conventions follow `canonical-table-groups-for-automaton-designs-2026-09-12.md`:
- a cellular automaton computes `tau(x)(g) = mu((x(g g_m))_(m in M))`;
- a design is `D = (A, S, M, nu, mu)`, with formal address sets containing identity
  addresses `1_S` and `1_M`;
- `E` is a marked partition of `S x M`, and `U_E` its table group;
- `𝓕_D` is the up-set of forward-sufficient partitions.

## 1. Presentations of holonomy shape

Call a finite presentation `P = <X | R>` **of holonomy shape** if every relator is an
equation

```text
u_r v_r^(-1) = w_r z_r^(-1),        u_r, v_r, w_r, z_r in X ∪ {1}.
```

**Lemma 1.** Every finite presentation is Tietze equivalent to one of holonomy shape.

*Proof.* For each generator `x`, adjoin a letter `x̄` and the relator `x 1^(-1) = 1 x̄^(-1)`,
i.e. `x̄ = x^(-1)`. For a relator word `y_1 ... y_n`, adjoin letters `p_1, ..., p_n` and the
following relators, with `p_0 = 1`:
- `p_i 1^(-1) = p_(i-1) x̄^(-1)` if `y_i = x`, which says `p_i = p_(i-1) x`;
- `p_i 1^(-1) = p_(i-1) x^(-1)` if `y_i = x^(-1)`, which says `p_i = p_(i-1) x^(-1)`;
- `p_n 1^(-1) = 1 1^(-1)`, which says `p_n = 1`.

Eliminating the new letters recovers the original relator. QED

## 2. The shift–shear design of a presentation

Fix `P = <X | R>` of holonomy shape. The design `D_P` is as follows.

**Alphabet.** `A = F_2^T` with tracks `T = {d} ⊔ {a_r, b_r : r in R}`: one data track and
two key tracks per relator.

**Encoder.** `M = {1_M} ⊔ X`, one memory address per generator. Write `x_t(g)` for
track `t` of `x(g)`, and let `tau` compute:

```text
tau(x)_(a_r)(g) = x_(a_r)(g v_r),
tau(x)_(b_r)(g) = x_(b_r)(g z_r),
tau(x)_d(g)     = x_d(g) + sum_(r in R) x_(a_r)(g u_r) · x_(b_r)(g w_r)      (over F_2).
```

When a letter is `1`, its address is `1_M`.

**Decoder.** `S = {1_S} ⊔ {ā_r, b̄_r, h_r : r in R}`, with realized values
`ā_r = v_r^(-1)`, `b̄_r = z_r^(-1)` and `h_r = u_r v_r^(-1)`. Let `sigma` compute:

```text
sigma(y)_(a_r)(g) = y_(a_r)(g ā_r),
sigma(y)_(b_r)(g) = y_(b_r)(g b̄_r),
sigma(y)_d(g)     = y_d(g) + sum_(r in R) y_(a_r)(g h_r) · y_(b_r)(g h_r).
```

**The shared address.** `sigma` reads both key tracks of relator `r` at the ONE decoder
address `h_r`. The decoder needs `x_(a_r)(g u_r)` and `x_(b_r)(g w_r)`, but the encoder
stores them at the shifted positions `g u_r v_r^(-1)` and `g w_r z_r^(-1)`. Reading
both at one address is exactly the relator `u_r v_r^(-1) = w_r z_r^(-1)`.

## 3. The forward table is principal and presents `P`

Let `E_P` be the marked partition of `S x M` whose only identifications are:

```text
(ā_r, v_r) and (b̄_r, z_r) in the marked class of (1_S, 1_M),
(h_r, v_r) ~ (1_S, u_r),         (h_r, z_r) ~ (1_S, w_r),
```

with `(1_S, x)` read as the marked class whenever `x = 1`.

**Lemma 2.** `E_P` is forward sufficient, and every forward-sufficient partition
dominates it. So `𝓕_(D_P)` is the principal up-set generated by `E_P`.

*Proof.*
- **The composite reads these cells.** `sigma(tau(x))(g)` reads
  - track `a_r` at cell `(ā_r, v_r)`,
  - track `b_r` at cell `(b̄_r, z_r)`,
  - track `d` at `(1_S, 1_M)`, and the key tracks at `(1_S, u_r)`, `(1_S, w_r)`,
    `(h_r, v_r)` and `(h_r, z_r)`.

  No other cell enters.
- **Sufficiency.** On `E_P` the key outputs return the marked symbol. The data output is
  the marked `d`-symbol plus, for each `r`, the sum of two equal products. So it is
  the marked symbol.
- **Domination: key tracks.** Let `E'` be forward sufficient. If `(ā_r, v_r)` is outside
  the marked class of `E'`, give its class an `a_r`-symbol different from the marked
  class's. Then output `a_r` is wrong. The same argument handles `b̄_r`.
- **Domination: data track.** If `(h_r, v_r)` and `(1_S, u_r)` are in different classes
  of `E'`, choose symbols as follows:
  - put `a_r = 1` on the class of `(1_S, u_r)` and `a_r = 0` on the class of `(h_r, v_r)`;
  - put `b_r = 1` on the classes of `(1_S, w_r)` and `(h_r, z_r)`;
  - put `0` on every other key track of every class.

  The data output is then the marked symbol plus `1·1 + 0·1 = 1`, which is wrong.
  Tracks of different relators are disjoint, so no other term interferes. The case
  `(h_r, z_r)` against `(1_S, w_r)` is symmetric. QED

**Lemma 3.** `U_(E_P) ≅ P`.

*Proof.* The relators of `U_(E_P)` are:

```text
x_(ā_r) x_(v_r) = 1,   x_(b̄_r) x_(z_r) = 1,   x_(h_r) x_(v_r) = x_(u_r),   x_(h_r) x_(z_r) = x_(w_r).
```

Eliminate `x_(ā_r)`, `x_(b̄_r)` and `x_(h_r) = x_(u_r) x_(v_r)^(-1)`, each private to one
relator. The fourth relator becomes `x_(u_r) x_(v_r)^(-1) x_(z_r) = x_(w_r)`, which is the
relator `r` of `P`. Identity letters are the empty word. QED

In holonomy coordinates (`table-groups-are-memory-holonomy-groups`), each relator `r`
contributes one independent cycle of the decoder difference graph: the two edges out of
`h_r`, closed through the root. So `b_1(Gamma_(E_P)) = |R|`.

## 4. The design is bijective over every group

**Lemma 4.** For every group `G` and every realization of `D_P` in `G`, `tau` is bijective.

*Proof.* `tau = gamma o beta`, where:
- `beta` translates each key track, `a_r` by `v_r` and `b_r` by `z_r`, and fixes `d`. It is
  bijective, with inverse the translations by `v_r^(-1)` and `z_r^(-1)`.
- `gamma` adds to `d` the sum over `r` of `y_(a_r)(g u_r v_r^(-1)) · y_(b_r)(g w_r z_r^(-1))`
  and fixes the key tracks. It is an involution.

This holds in every group whether or not the relators of `P` hold. When they do, the
decoder of Section 2 equals `tau^(-1)`. QED

## 5. Consequences

**Theorem F.** For every finite presentation `P` there is a design `D` over `F_2^T` such that:
- `𝓕_D` is principal, generated by a partition `E`;
- `U_E ≅ P`, with one independent cycle per relator;
- the realization of `D` over every group, `U_E` included, is bijective.

*Proof.* Lemmas 1 to 4. QED

**Corollary 1 (forcing is not strictness).**
- Nonsoficity or property (T) of the forced core never certifies strictness. Take `P`
  to present:
  - the nine-leaf configuration `Gamma <= EL_alpha(R)` with its compressor and nesting
    relators (`openai-nine-leaf-leavitt-configuration`);
  - or, if its finite presentation is imported, the Leavitt unit group itself.

  `D_P` forces that Kazhdan, nonsofic core with any number of independent cycles, and
  it is bijective.
- `forward-relations-of-a-counterexample-have-a-nonsofic-core` states a necessary
  condition. Theorem F shows that no strengthening of it reading only the core's
  isomorphism type can be sufficient.

**Corollary 2 (the death point of defect-window designs moves).** "No rule pair is
known whose forward sufficiency needs a Kazhdan presentation" is resolved: shift–shear
pairs need it. What no known rule pair does is keep a reverse hinge alive while forcing
such a core. By Theorem A of the canonical-table artifact, strictness over `U_E` is the
survival of a hinge word for every minimal reverse partition. For `D_P` every reverse
hinge dies, because `tau` is invertible by a formula valid in the free group on the
memory letters.

**Corollary 3 (composition with bijective gadgets).** If `beta` is bijective over `G`, then
`tau` is strict over `G` exactly when `beta o tau` or `tau o beta` is. Shift–shear gadgets
can therefore enlarge the forced core of a design arbitrarily without changing its
strictness over any group. A counterexample's decisive coincidences must come from
the irreversible part of its rules. Section 2 of the canonical-table artifact already
shows that relations the decoder does not need add nothing.

## 6. What the design program needs next

The target is sharpened, not solved. A strict design needs rules whose forward
sufficiency forces relators of the shape `s m = s' m'` and whose reverse sufficiency, for
every minimal reverse partition, needs a coincidence `m s = m' s'` that is not a
consequence in `U_E`. In shift–shear designs every reverse coincidence is a formal
consequence of the forward ones: the inverse automaton is built from inverse
translations and the same shear. Candidate sources of non-consequence:
- **left–right transposition.** `u v^(-1) = w z^(-1)` does not imply `v^(-1) u = z^(-1) w`.
  A rule pair whose reverse composite reads cancellations on the left of the memory
  would need the transposed relator.
- **linear rules.** For linear rules over `F_2` the reverse identity is Kaplansky direct
  finiteness in `F_2[U_E]`. It holds on sofic cores, through soficity and not through a
  syntactic consequence of the forward relators.

These are open design directions, not results.
