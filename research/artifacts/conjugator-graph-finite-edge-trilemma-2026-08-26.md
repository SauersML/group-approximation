# The finite-edge trilemma for the conjugator graph

## Status

This is a Cairn-only audit of the genuinely nonretractive, nonnormal route to
`Higman.Star.ConjugatorGraph.graph_benign`.  It examines the repository's
actual `RopeTrick`, `Pinch`, `PinchGraph`, `FlipGroup`, `HNNDescent`,
`HNNEmbedding`, `RowSubgroup`, and `ExplicitFreeEdge` constructions.

It does not produce the missing witness.  It isolates one new exact
relation-pattern firewall and a three-way obstruction shared by every existing
module:

1. `Pinch` and `HNNDescent` prove the desired intersection once a stable edge
   has already been supplied, but putting the graph itself in the seed or edge
   makes that datum infinitely generated.
2. `FlipGroup` compresses the conjugate family through finitely generated,
   finitely presented, torsion-free HNN edges, but identifying its walkers with
   the graph's second coordinate collapses the original free group.
3. `HNNEmbedding` can absorb an arbitrary countable payload without that
   collapse, but its associated subgroups are free of countably infinite rank,
   so its extension is only a finite-generation device, not a finite-presentation
   device.

The missing construction is therefore narrower than “use Britton's lemma”:
it must be a finite-edge transducer that carries the graph value without
either making un-conjugation homomorphic or identifying a conjugating walker
with a commuting second-coordinate letter.

No Lean, build, MSI, or external input was used.

## 1. Target and notation

Let

\[
  A=\mathbb F(a,b,c),\qquad K=\langle b,c\rangle\leq A,
  \qquad D=A\times A,
\]

and write

\[
  \gamma_h=(h^{-1}ah,h)\qquad(h\in K).
\]

The target is

\[
  \Gamma=\langle\gamma_h:h\in K\rangle\leq D.
\]

It is free on the displayed family.  Consequently it has countably infinite
rank and is not finitely generated.

A successful result must give a finitely presented torsion-free group \(P\),
an embedding \(D\hookrightarrow P\), and a finitely generated subgroup
\(L\leq P\) with

\[
  D\cap L=\Gamma.
\]

The previous audits show that \(D\) can be neither a retract nor a direct
factor of such a witness.  This note only considers the remaining HNN and
graph-of-groups mechanisms.

## 2. What `HNNDescent` would prove if the edge existed

The theorem `HNNDescent.closure_inf_range` has exactly the correct normal-form
shape.  Given an HNN extension

\[
  E=\langle P,t\mid tAt^{-1}=B\rangle
\]

and a subgroup \(Z\leq P\) stable under both partial edge maps, it proves

\[
  \langle Z,t\rangle\cap P=Z.
\]

The proof is the needed Britton descent: a word in \(Z\) and \(t\) either has
a pinch, which stability collapses back into \(Z\), or is reduced and cannot
lie in the base.

For benignness one cannot put \(Z=\Gamma\) directly in the generating set,
because \(\langle Z,t\rangle\) is then not known to be finitely generated.
One needs a finite seed \(S\subseteq\Gamma\) such that

\[
  \Gamma\leq\langle S,t_1,\ldots,t_m\rangle
\]

while each edge group remains finitely generated.  `HNNDescent` verifies the
intersection after those data are built; it does not build them.

This distinction matters.  Every HNN extension below is automatically safe
for torsion once its base is torsion-free.  The binding issue is finite edge
data, not torsion or Britton's lemma.

## 3. Why `Pinch` and `PinchGraph` do not manufacture the missing finite seed

### 3.1 `Pinch`

In the central HNN extension \(P*_M t\), `Pinch.pinch` computes

\[
  \langle Z,Q^t\rangle\cap P=Z

\]

under the two crossing conditions

\[
  Q\cap M\leq Z,
  \qquad
  Z\cap M\leq Q.
\]

Putting \(Z=\Gamma\) gives the desired intersection formally, but the cutter
is generated by \(Z\) together with \(Q^t\).  The construction has not
compressed \(Z\); it has merely protected it during Britton reduction.  Since
\(\Gamma\) is not finitely generated, this is not a benign witness.

Taking \(Z\) finitely generated avoids that problem but changes the
intersection to \(Z\), not \(\Gamma\).  There is no iteration inside `Pinch`
that enlarges the base intersection beyond the stable subgroup provided as
input.

### 3.2 `PinchGraph`

`PinchGraph.blockGraph` attaches a value homomorphism

\[
  \phi:A_0\longrightarrow T

\]

to the subgroup generated by \(A_0\) and its stable conjugate.  Its graph is
generated by

\[
  (x,\phi x),\qquad (x^t,1)qquad(x\in A_0).
\]

There are exactly two obvious choices for the present target, and each fails
for a different exact reason.

* If \(A_0\) is a finitely generated subgroup containing the ambient
  \(a,b,c\) data, then obtaining \((a^h,h)\) asks the value homomorphism to
  send \(a^h\) to \(h\).  At \(h=1\) it kills \(a\), and hence kills every
  conjugate of \(a\).  This is the already proved no-un-conjugation identity,
  not a missing normal-form argument.
* If \(A_0\) is instead the abstract free group on the family
  \(\{a^h:h\in K\}\), the evaluation \(a^h\mapsto h\) is a valid
  homomorphism, but \(A_0\) has infinite rank.  The displayed generating
  family for `blockGraph` is then infinite, so it does not give a finitely
  generated cutter.

Thus `PinchGraph` cleanly handles “finite domain plus homomorphic value” and
“infinite graph domain plus evaluation,” but the target requires both finite
generation and the second behavior simultaneously.

## 4. The flip tower supplies the tempting finite walkers

`FlipGroup` builds a finitely presented torsion-free group \(G_2\) containing
an injective copy

\[
  \operatorname{emb}:A\hookrightarrow G_2

\]

and elements \(\beta,\gamma\) such that

\[
\begin{aligned}
  \beta\operatorname{emb}(a)\beta^{-1}
    &=\operatorname{emb}(b^{-1}ab),\\
  \gamma\operatorname{emb}(a)\gamma^{-1}
    &=\operatorname{emb}(c^{-1}ac),
\end{aligned}
\]

while \(\beta,\gamma\) commute with
\(\operatorname{emb}(K)\).  More generally, its left copy

\[
  f_0:K\longrightarrow G_2,
  \qquad f_0(b)=\beta,\quad f_0(c)=\gamma,
\]

satisfies

\[
  f_0(h)\operatorname{emb}(a)f_0(h)^{-1}
  =\operatorname{emb}(h^{-1}ah).
\]

This is exactly the finite collection mechanism absent from a raw central
HNN extension.  It is therefore natural to try to identify the left walker
copy \(f_0(K)\) with the second-coordinate copy of \(K\) in \(D\).

That identification is impossible for a one-relation reason.

## 5. New exact firewall: the flip walker cannot be the second coordinate

### Theorem 5.1 — flip/commuting-coordinate collision

Let \(P\) contain an injective copy \(i:D\hookrightarrow P\).  There is no
element \(v\in P\) satisfying both

\[
  [v,i(a,1)]=1

\]

and

\[
  v,i(a,1),v^{-1}=i(b^{-1}ab,1).

\]

### Proof

The commutator relation makes the left side of the second equation equal to
\(i(a,1)\).  Hence

\[
  i(a,1)=i(b^{-1}ab,1).
\]

Injectivity of \(i\) gives

\[
  a=b^{-1}ab

\]

in the free group \(A\), or \([a,b]=1\).  But the reduced word

\[
  a^{-1}b^{-1}ab

\]

has four letters and no cancellation, so it is not the identity.  This is a
contradiction. \(\square\)

### Corollary 5.2 — the natural flip amalgam collapses the double

Suppose an amalgam or HNN edge identifies \(\beta=f_0(b)\) with the embedded
second-coordinate element \(i(1,b)\).  In \(D\), the two direct factors
commute, so

\[
  [i(1,b),i(a,1)]=1.
\]

The flip relation simultaneously says

\[
  i(1,b)i(a,1)i(1,b)^{-1}=i(b^{-1}ab,1).
\]

Theorem 5.1 shows that the map \(D\to P\) is not injective.  The same argument
with \(c\) rules out identifying \(\gamma=f_0(c)\) with \(i(1,c)\).

The collision uses neither a retraction nor normality of \(D\).  It therefore
survives in the genuinely nonretractive graph-of-groups setting left open by
the previous audits.

### Corollary 5.3 — enlarging the flip edge does not help

Any finite edge group whose relations retain both

* the flip action \(f_0(h)\operatorname{emb}(a)f_0(h)^{-1}
  =\operatorname{emb}(a^h)\), and
* the direct-product commutation between the proposed second-coordinate
  \(h\) and the first-coordinate \(a\),

collapses \(a^h\) to \(a\).  The problem is the two required relations
themselves, not the size or presentation of the edge group.

Thus the repository's strongest finite conjugate collector cannot simply be
wired into the second coordinate.

## 6. Why `RowSubgroup` has the same mismatch

`RowSubgroup` succeeds because one automorphism of a finitely generated free
base shifts the entire target family:

\[
  t b_i t^{-1}=b_{i+1}.

\]

The stable letter has no independent coordinate payload.  For the graph,
shifting the first component from \(a^h\) to \(a^{bh}\) while also treating
the same walker as a second-coordinate letter invokes Theorem 5.1.  Keeping
the walker external avoids collapse, but then conjugation cannot change the
second coordinate from \(1\) to \(h\); products or a separate value graph are
needed, returning to the `PinchGraph` dichotomy.

So the row construction supplies finite orbit collection, but not correlated
orbit-and-value collection.

## 7. Why `HNNEmbedding` is not a finite-presentation repair

`HNNEmbedding` handles an arbitrary countable payload \(g_i\) by putting, in
the free product \(A*F(x,y)\),

\[
  a_i=x^{-i}yx^i,
  \qquad
  b_i=g_i a_i,

\]

and adjoining a stable letter with

\[
  t a_i t^{-1}=b_i

\]

for every \(i\).  The repository proves that both families freely generate
associated subgroups of countably infinite rank.  The resulting extension is
three-generated and contains the payload group.

This is exactly the nonretractive, nonnormal shape one would want for an
enumeration of \(\Gamma\), but its edge is

\[
  \mathbb F\{a_i:i\in\mathbb N\}

\]

and is not finitely generated.  The finite-presentation HNN theorem therefore
does not apply.  This is why `HNNEmbedding` proves an `FGOvergroup`, not an
`FPOvergroup`.

The failure is not merely absent API.  A finite presentation of that exact
HNN relation table would have to derive all payload relations
\(ta_it^{-1}=g_i a_i\) from finitely many of them.  For an arbitrary
enumeration \(g_i\), no such recurrence is present.  For the present graph a
recurrence does exist abstractly—the basepointed Nielsen envelope—but the
flip collision proves that the repository's finite ambient recurrence cannot
also be the commuting second coordinate.

## 8. `ExplicitFreeEdge` verifies edges; it does not shrink them

`ExplicitFreeEdge.Data` packages two injective evaluations of the same finite
rank free group and turns them into an honest HNN extension.  The `sigma`,
`d`, and Nielsen-shear sections are valuable once finite source and target
tuples have been found.

For \(\Gamma\), however, the missing datum is precisely such a finite tuple.
Using one source generator for every \(h\in K\) recreates the infinite edge of
`HNNEmbedding`.  Using only \(a,b,c\) asks a homomorphism or flip walker to
propagate the values, triggering respectively the no-un-conjugation theorem or
Theorem 5.1.  `ExplicitFreeEdge` faithfully exposes this obligation and does
not provide a hidden compression theorem.

## 9. `RopeTrick` is downstream, not a bootstrap

`RopeTrick` begins with a `BenignWitness N`.  Its first central HNN extension
uses that witness's finitely generated cutter, and its second HNN extension
turns the quotient value into finitely many relations.  It proves that a
quotient by a benign normal subgroup embeds in a finitely presented group.

Applying it to the present leaf would require benignness before the
construction starts.  Moreover \(\Gamma\) is self-normalizing and nonnormal in
\(D\), so it is not the normal subgroup \(N\) required by the rope theorem.
Passing to its normal closure changes the intersection target.  Thus
`RopeTrick` cannot serve as a noncircular graph witness.

## 10. The finite-edge trilemma

The module audit reduces the remaining design space to the following exact
trilemma.

### Route A — homomorphic value

Use `PinchGraph` or a graph edge to attach the second coordinate by a
homomorphism.  On a finitely generated ambient domain this requires

\[
  a^h\longmapsto h,

\]

which is impossible already at \(h=1\).

### Route B — finite conjugate walker

Use `FlipGroup` or `RowSubgroup` to collect all \(a^h\) from finitely many
seeds.  Identifying that walker with the commuting second-coordinate \(h\)
forces

\[
  a=a^h

\]

and destroys injectivity of \(D\).

### Route C — arbitrary payload edge

Use `HNNEmbedding` to carry the pair \((a^h,h)\) as an indivisible payload.
This preserves injectivity but uses an associated free group with one basis
element per payload, hence an infinitely generated edge and no finite
presentation.

The missing object must escape all three routes.  Concretely, it must be:

> A finite-rank edge whose normal forms carry a nonhomomorphic value, whose
> walker is not the commuting value letter, and whose finite relations still
> derive the whole graph family.

None of the audited repository modules contains such an object.

## 11. Lean-facing boundary

The useful existing proof endpoint is `HNNDescent.closure_inf_range`.  A future
construction should aim to supply:

1. a finitely presented torsion-free base containing \(D\);
2. finitely generated associated subgroups and explicit equivalences;
3. stability of \(\Gamma\) under those partial equivalences;
4. a finite seed whose stable-letter closure contains every \(\gamma_h\).

Once these four facts exist, the repository already has the Britton descent,
finite-presentation theorem, and torsion theorem needed to package the benign
witness.  Reformalizing `Pinch`, `HNNDescent`, or HNN torsion would not address
the missing mathematics.

No inhabitant of `ConjugatorGraph` is claimed here.
