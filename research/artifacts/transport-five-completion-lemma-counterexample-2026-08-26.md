# The `Transport.CompletionLemma` leaf is false

Date: 2026-08-26

This note audits only the structure

```lean
structure GroupApproximation.Higman.Transport.CompletionLemma where
  section_mem :
    ∀ (n : ℕ) (N : Subgroup (FreeGroup (Fin (n + 1)))), N.Normal →
      ∀ w ∈ N, sectionHom n w ∈ codeSub n N
```

from `GroupApproximation/Higman/TransportFive.lean`.  It uses no external
result.  The asserted field is false for `n = 0`.

## 1. Specializing the definitions to rank one

Put

\[
F=F(\{g\})\cong\mathbb Z,
\qquad
N=\langle g^3\rangle.
\]

Equivalently, `N` is the kernel of exponent sum modulo three, so `N` is a
normal subgroup of `F`.  Let

\[
w=g^3\in N.
\]

For `n = 0`, the alphabet is `Fin 1`.  Every raw index names its unique
letter, and

\[
\operatorname{pos}(0,k,i)=k.
\]

Write `x_k` for the generator `FreeGroup.of (k : ℤ)` of `FreeGroup ℤ`.
If a nonempty raw word has signs

\[
\varepsilon_0,\ldots,\varepsilon_{L-1}\in\{+1,-1\},
\]

then its block code evaluates to

\[
x_0^{\varepsilon_0}x_1^{\varepsilon_1}\cdots
x_{L-1}^{\varepsilon_{L-1}}.
\]

The raw word represents an element of `N` exactly when

\[
\varepsilon_0+\cdots+\varepsilon_{L-1}\equiv0\pmod3.
\]

Consequently, `codeSub 0 N` is generated by all such words.  On the other
hand,

\[
\operatorname{sectionHom}(0)(w)=x_0^3.
\]

We now separate `x_0^3` from `codeSub 0 N` by an explicit four-point
permutation action.

## 2. A two-generator image containing every block code

Let `F(a,b)` be the free group on `a,b`, and define a homomorphism

\[
\phi:F(\mathbb Z)\longrightarrow F(a,b)
\]

on the free basis by

\[
\phi(x_0)=a,
\qquad
\phi(x_k)=b\quad(k\ge1).
\]

The values on the unused negative-index generators may be chosen arbitrarily;
take them to be the identity.

Set

\[
c=ab^{-1},
\qquad
d=a^{-1}b,
\qquad
H=\langle c,d,b^3\rangle\le F(a,b).
\]

Every generator of `codeSub 0 N` maps into `H`.  Indeed, for a nonempty code
put

\[
T=\varepsilon_1+\cdots+\varepsilon_{L-1}.
\]

If `\varepsilon_0=+1`, divisibility of `1+T` by three gives
`T=3q-1`, and hence

\[
\phi(\operatorname{code}(v))=ab^{3q-1}=c(b^3)^q\in H.
\]

If `\varepsilon_0=-1`, divisibility of `-1+T` by three gives
`T=3q+1`, and hence

\[
\phi(\operatorname{code}(v))=a^{-1}b^{3q+1}=d(b^3)^q\in H.
\]

The empty code maps to the identity.  Since `H` is a subgroup, this proves

\[
\phi(\operatorname{codeSub}(0,N))\le H.
\tag{1}
\]

## 3. A four-point witness that `a^3` is not in `H`

Let `a` and `b` act on `\Omega=\{0,1,2,3\}` by the permutations

\[
A=(0\ 1\ 3\ 2),
\qquad
B=(0\ 1\ 2),
\]

where `B` fixes `3`.  Using the standard convention
`(\sigma\tau)(x)=\sigma(\tau(x))`, direct evaluation gives

\[
(AB^{-1})(0)=A(2)=0,
\]

\[
(A^{-1}B)(0)=A^{-1}(1)=0,
\]

and

\[
B^3(0)=0.
\]

Thus every element of `H=\langle ab^{-1},a^{-1}b,b^3\rangle` fixes `0`.
But

\[
A^3(0)=2\ne0.
\]

Therefore

\[
a^3\notin H.
\tag{2}
\]

Combining (1) and (2),

\[
x_0^3\notin\operatorname{codeSub}(0,N).
\]

Since `x_0^3 = sectionHom 0 (g^3)` and `g^3 \in N`, the proposed
`CompletionLemma.section_mem` conclusion fails.

## 4. The suggested kernel route also fails independently

The comments in `TransportFive.lean` propose the stronger sufficient claim

\[
\ker(\operatorname{decodeHom} n)\le\operatorname{codeSub}(n,N).
\]

That cannot hold for the present coding.  Take `N=1`.  Every `codeSeq` starts
at block zero, so every generator of `codeSub n 1` uses only nonnegative
positions.  Hence `codeSub n 1` lies in the free factor generated by
`\{x_p:p\ge0\}`.  But, for example,

\[
x_{-1}x_q^{-1}\in\ker(\operatorname{decodeHom} n)
\]

whenever `q\ge0` has the same residue modulo `n+1` as `-1`; this reduced word
contains the negative-position generator `x_{-1}` and therefore is not in that
free factor.

So the kernel-generation route is not merely unfinished: it is incompatible
with the current one-sided, block-zero-starting code.

## 5. Consequence for the formalization

There can be no assumption-free inhabitant of the current
`Transport.CompletionLemma`.  The leaf must be redesigned before Lean work is
meaningful.  In particular, adding an induction on descents cannot repair the
statement: the rank-one cubic example above has no descent issue at all and is
already separated by a finite permutation action.

Any repair has to change the coding interface or the assembly.  It must supply
enough additional coded generators to recover the section of `N`; merely
proving more facts about the existing `codeSeq n v 0` family cannot do so.
