**ESTABLISHED.** The lower bound is imported. The upper bound is an exact
rational certificate produced by a script that checks itself.

## Statement

`331440289/227504128 <= R*(4) <= U_4`. Here `U_4 ~ 1.534726256` is the exact
rational on the `exact:` line of `fold_ub2_k4_run1.log`.

## Lower bound

This is imported. Martinsson (arXiv:2408.04832) writes, verbatim, "Wiman's
Max-Had 4 gadget has c = 15/16 and s = 3308625759/3640066048 ≈ 0.9089". The
soundness there is relaxed, and relaxed soundness is at least true
soundness, so the bound holds for true soundness too.

* **Deletion ratio.** In deletion form this is
  `(1 - s)/(1 - c) = 331440289/227504128 ~ 1.4568540`.
* **Independent check.** `verify_certificate.py` certifies the gadget
  printed in `results-2026-09-19.txt` exactly, with value
  `905957293/621871104 ~ 1.456825`. This is Wiman's value after rounding the
  weights to integers.
* **Relaxed optimum.** The unfolded column generation uses exact min-cut
  pricing and converges to `1.456854`. So Wiman's gadget is optimal for the
  relaxation, up to LP floating-point tolerance. This last point is
  numerical only and is not part of the claim.

## Upper bound

`hadk_fold_ub2.py` produces an explicit finite family of folded
`f : {-1,1}^16 -> {-1,1}`, 35 columns in all. It then does the following:

* **Pins.** For each column, it re-checks `f(-x) = -f(x)` and the pins
  `f(chi_a) = xi_a`, where `xi` is the representative of the column's
  pattern orbit.
* **Cut counts.** It stores the integer number of cut edges in each of the
  23 edge orbits.
* **Exact weights.** It assigns rational weights whose total on each
  pattern orbit is exactly `|orbit| / 2^16`.
* **Symmetrization.** It averages over the symmetry group, generated by the
  affine maps of `F_2^4` and by negation. By orbit-stabilizer, the result is
  a folded distribution random on `P`.
* **The bound.** Its cut probability on edge orbit `o` is
  `sum_c p_c cnt_c(o) / |o|`, computed exactly. Then `R*(4) = 16 z*` is at
  most 16 times the largest of these, which is `U_4`.

The pricing that chose the columns is heuristic, and this does not affect
validity.

## Consequence

* The window for `R*(4)` shrinks from `[1.4569, 1.6583]` to
  `[1.4569, 1.5348]`.
* By `hadamard-crossing-needs-folding-gap`, the folding gap `Delta(4)` lies
  in `[0, 0.0779]`.
* Whether `Delta(4) > 0` is `hadamard-gadget-k4-true-soundness-beats-wiman`.
